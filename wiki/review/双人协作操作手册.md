# 双人协作操作手册：生成者与校准者

本手册适用于 [[review/可穿戴睡眠检测与闭环干预综述]]。生成者负责整理证据和起草；校准者负责逐句核验、决定是否放行。唯一进度记录见 [[review/综述写作看板]]，唯一已确认正文见 [[review/综述正文草案]]。

## 一、角色边界

| 角色  | 可以做                                                     | 不能做                       |
| --- | ------------------------------------------------------- | ------------------------- |
| 生成者 | 提出文献需求、处理用户放入 `raw/inbox/` 的素材、建立证据包、生成受限草案和段落证据矩阵、更新看板 | 自行确认段落、用未提供文献补写、在校准中改写同一段 |
| 校准者 | 下载/补充全文、核对原文与草案、标记缺口、退回或确认版本、决定是否进入正文草案                 | 把无来源信息作为事实放行、跳过证据矩阵直接合并   |

## 二、状态与放行门槛

```text
待开始
  → 证据包中
  → 生成中
  → 待校准
  → 校准中
  → 已确认 → 写入正文草案 → 整合小节
        ↘ 需返工 → 生成中
        ↘ 阻塞：缺证据 → 用户补全文 → Ingest → 证据包中
```

| 当前状态 | 谁操作 | 允许进入下一步的条件 | 下一状态 |
| --- | --- | --- | --- |
| 待开始 | 校准者提出目标；生成者响应 | 已明确一个最小段落和它要回答的问题 | 证据包中 |
| 证据包中 | 生成者 | 每项主张均有用户提供的全文、来源页和定位；否则列出缺口 | 生成中 / 阻塞：缺证据 |
| 生成中 | 生成者 | 已有单段草案、段落证据矩阵、限制说明 | 待校准 |
| 待校准 | 校准者 | 已分配校准人，版本号已写入看板 | 校准中 |
| 校准中 | 校准者 | 完成逐句核验及上下文检查 | 已确认 / 需返工 / 阻塞：缺证据 |
| 已确认 | 生成者 | 校准结论及修改历史已登记 | 写入正文草案；可开始下一段 |
| 需返工 | 生成者 | 已逐条响应校准意见并提升版本号 | 待校准 |
| 阻塞：缺证据 | 校准者/用户 | 用户补齐完整资料并完成 Ingest | 证据包中 |

## 三、每一轮的标准操作

### 步骤 A：选段与文献需求

**校准者发送：**

```text
我要写第 2.3 节，请给我文献需求单。
目标问题：系统从采集到刺激执行的时延和触发精度如何报告？
```

**生成者交付：** 必需/推荐/背景文献候选、每篇要提取的字段、不可替代的证据、缺口与检索关键词；不写正文。

**可进入下一步，当且仅当：** 校准者确认要下载的全文清单，或明确某项暂时保留为 `gap`。

### 步骤 B：下载、入库与准入

**校准者执行：** 将完整 PDF 放入 `raw/inbox/`，再发送：

```text
处理 raw/inbox 全部素材。
```

**生成者交付：** 来源页、实体词条、证据矩阵更新、准入/不准入清单及不准入原因。

**可进入下一步，当且仅当：** 每篇拟引用文献都有可读全文、稳定 `source_id`、来源页和页码/表图定位；否则回到补文献。

### 步骤 C：阅读澄清与证据包

**校准者发送：**

```text
阅读第 2.3 节已准入文献，先报告不清楚与缺口。
```

**生成者交付：** 缺页/版本、方法、参数、对照、时延、终点和安全性等不清楚项；并说明每个缺口应补哪类文献。随后发送：

```text
为第 2.3 节建立证据包，只用 A、B、C 三篇文献。
```

**生成者交付：** “可写主张—来源—页码/表图—适用条件—限制”表。

**可进入下一步，当且仅当：** 校准者确认该证据包没有用相近概念替代直接证据；每一条待写事实均可追溯。否则补资料或缩小段落目标。

### 步骤 D：生成单段与证据矩阵

**校准者发送：**

```text
按已确认的 2.3 证据包生成第 2.3-P1 v1。
```

**生成者交付：** 一个段落、段落核验清单和逐句段落文献证据矩阵（本文句子—原文短语—来源页—页码/表图—条件—限制）。同时将看板状态更新为 `待校准`。

**可进入下一步，当且仅当：** 段落中的每个事实都在矩阵中有原文指针；无来源内容已移出正文或标为 `【待补证据】`。

### 步骤 E：人工校准与决定

**校准者发送：**

```text
校准第 2.3-P1 v1。
```

**校准者执行：** 按范围、来源、原文忠实度、证据层级、方法比较、完整性和上下文衔接逐句检查。

**校准者交付：** `已确认`、`需返工` 或 `阻塞：缺证据`；逐句理由、缺失资料和下一动作均写入 [[review/综述写作看板]]。

**可进入下一步：**

- `已确认`：生成者写入正文草案，可同时开始下一段的证据包；
- `需返工`：生成者只改该段，版本号升为 v2 后重新校准；
- `阻塞：缺证据`：回到步骤 A/B，不写结论性正文。

### 步骤 F：合并与章节推进

**校准者发送：**

```text
整合第 2.3 节。
```

**生成者交付：** 仅合并所有“已确认”的段落到 [[review/综述正文草案]]，更新章节页、证据矩阵和看板。

**可进入下一节，当且仅当：** 本节所有目标问题已回答或已明确登记为 `gap`；没有未处理的 `需返工`；段落之间没有证据层级跳跃。

## 四、并行排程示例

| 时间段 | 生成者 | 校准者 |
| --- | --- | --- |
| 第一轮 | 为 2.1-P1 建立证据包 | 下载/核对 2.1-P1 的全文 |
| 第二轮 | 起草 2.1-P1 v1；为 2.1-P2 找证据 | 校准 2.1-P1 v1 |
| 第三轮 | 按反馈修改 2.1-P1 v2 或起草 2.1-P2 | 确认 2.1-P1 v2；准备 2.2 文献需求 |

原则：相邻段落可并行；同一段落同一版本不可并行编辑。

## 五、每日收尾命令

```text
更新综述写作看板。
```

生成者或校准者需更新：当前段落版本、生成/校准状态、责任人、缺失资料、下一步和修改历史。该命令不改写正文。
